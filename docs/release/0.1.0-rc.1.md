# Cogniform 0.1.0-rc.1 source candidate notes

Status: unpublished candidate. These notes describe the reviewed source tree
being prepared by CF051; they are not a release announcement and do not
authorize a tag, asset upload, or publication.

## Intended audience

This candidate is for early local evaluation by Rust developers who can build
the complete source archive with the pinned toolchain and vendored dependency
tree. It is not a production service, hosted control plane, stable library API,
or prebuilt application.

## Candidate contents

- deterministic bounded scene patches, atomic revisioned world mutation,
  stable external identity, logical queries, replay, recovery, and explicit
  asset persistence/rehydration;
- a headless `wgpu` renderer with bounded color, normalized depth, exact entity
  identity, structured visibility, and quantized world-space normal
  observations for the documented primitive and GLB subset;
- deterministic primitive imagination compilation and pure bounded built-in
  procedures;
- the local CLI scenario and diagnostics plus fixed inherited-stream binary and
  MCP `2025-11-25` stdio adapters; and
- a deterministic project-owned uncompressed source tar format and exact
  SHA-256 sidecar verifier for a separately approved annotated candidate tag.

All sixteen workspace packages are versioned `0.1.0-rc.1` and retain
`publish = false`. The crates are not published to crates.io, and their public
Rust APIs are not semver-stable.

## Validated profile

The controlled runtime profile is Windows 11 x86_64, Rust 1.97.1, and one
Vulkan discrete GPU satisfying the documented `wgpu` capability checks. The
standard Ubuntu GitHub runner is the build, lint, unit-test, documentation,
package-policy, and source-hygiene gate; its exact pull-request evidence remains
pending until the candidate branch is published for review. Linux GPU runtime, Windows
DX12 runtime, software adapters, macOS/Metal, mobile, and browser/WebGPU are not
supported by this candidate.

## Important limitations

- No listener, remote transport, authentication, authorization,
  confidentiality, freshness, replay/rate/tenancy policy, production SLA, or
  process supervision is supplied.
- Stdio adapters trust one parent-owned local process and must be discarded
  after a transport or service failure.
- Recovery and asset-source files are explicit create-new plaintext local
  artifacts. Their digests detect corruption but do not authenticate writers,
  select freshness, prevent rollback, encrypt data, or provide crash-atomic
  directory/catalog updates.
- Asset support is a strict bounded GLB/PNG subset. There is no automatic asset
  discovery, catalog, eviction policy, or rehydration.
- Rendering omits shadows, ambient/image-based lighting, spot lights, emissive
  and alpha modes, HDR/tone mapping, arbitrary shaders, animation, physics, and
  the wider texture/material surface.
- Performance reports are one-machine informational observations, never a
  portable threshold.

The complete limitations and operational rules are maintained in the

## Candidate verification and publication boundary

Before any publication, the exact squash-merged `main` commit must pass the
entire checklist and receive explicit maintainer tag authority. A separately
approved annotated `v0.1.0-rc.1` tag must bind that commit; the project-owned
tar and checksum must then be prepared and independently reverified without a
repository change. The exact tag, archive hash, these notes, support statement,
residual risks, repository release-immutability policy, and final draft release
must all be reviewed before a separate publication authorization.

If the candidate is defective, do not move a published tag or replace its
asset. Correct the source through a reviewed change and use an incremented
candidate identity.
